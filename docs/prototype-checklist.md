# Проверка прототипа на Android

Цель: до разработки собственного приложения проверить, что выбранный сервер и протокол работают в целевых сетях, а правила маршрутизации соответствуют ожиданиям.

Все пункты пока не выполнены. Покупку, конфигурацию сервера и результаты тестов фиксируем по мере работы. Секреты и полные клиентские конфигурации в репозиторий не добавляем.

## 1. Подготовка

- [ ] Выбрать VPS за пределами России с итоговой стоимостью до 300 ₽ в месяц; проверить цену продления, IPv4, комиссии и лимит трафика.
- [ ] Проверить доступный способ оплаты, предпочтительно российской картой, и условия использования VPN.
- [ ] Арендовать сервер на один месяц после выбора конкретного предложения.
- [ ] Настроить сервер и отдельный доступ для тестового телефона.
- [ ] Выбрать готовый Android-клиент, поддерживающий выбранный протокол, DNS и необходимые правила маршрутизации.
- [ ] Зафиксировать модель телефона, версию Android, версии клиента и серверного движка, страну сервера и дату проверки.
- [ ] Выключить AdGuard VPN и другие VPN на тестовом телефоне.
- [ ] Подготовить тестовые домены: `.ru`, `.рф`, российский сервис вне этих зон и иностранный сайт. Для проверки маршрутов использовать диагностику клиента и подходящие средства проверки внешнего IP.

## 2. Подключение в обеих сетях

Выполнить отдельно на домашнем Wi-Fi ВестКолл и на мобильном интернете Мегафона.

- [ ] Соединение с сервером устанавливается.
- [ ] Иностранный сайт открывается через VPN; диагностика и проверка внешнего IP подтверждают маршрут через сервер.
- [ ] Обычный просмотр страниц и воспроизведение видео работают без заметных постоянных обрывов.
- [ ] Записаны результаты проверки скорости и задержки напрямую и через VPN, время и условия измерения. Числовые пороги приемлемости согласуются по результатам первого теста.

## 3. Автоматические правила

- [ ] `.ru` и его поддомены идут напрямую.
- [ ] `.рф` работает напрямую, включая корректную обработку IDNA.
- [ ] Домен вида `example.ru.external.com` не ошибочно распознаётся как `.ru`; достаточно проверки сопоставления правил без обращения к этому примеру.
- [ ] Российский сервис вне `.ru`/`.рф`, включённый в набор правил, идёт напрямую.
- [ ] Неизвестное назначение идёт через VPN.
- [ ] Локальный адрес домашнего роутера доступен напрямую.
- [ ] Российский и иностранный сайты работают одновременно с разными маршрутами.
- [ ] Страница со сторонними ресурсами загружается корректно; проверены маршруты нескольких её доменов.
- [ ] Ручное исключение «через VPN» перекрывает правило `.ru`.
- [ ] Ручное исключение «напрямую» перекрывает маршрут по умолчанию.
- [ ] Удаление исключения возвращает автоматическое поведение для новых соединений.

## 4. DNS, IPv6 и восстановление

- [ ] DNS-запросы для назначений через VPN не уходят напрямую к провайдеру; проверка включает диагностику DNS, а не только внешний IP браузера.
- [ ] При доступном IPv6 трафик не обходит назначенный VPN-маршрут. Если IPv6 в тестовой сети отсутствует, это отмечено как непроверенное условие.
- [ ] Проверено поведение браузера с собственным защищённым DNS; ограничения распознавания доменов записаны.
- [ ] После Wi-Fi → мобильная сеть и обратного переключения соединение восстанавливается.
- [ ] После краткой потери сети и после сна телефона соединение восстанавливается.
- [ ] При недоступности VPN-сервера иностранные назначения не переключаются напрямую, а прямые назначения продолжают работать при активной VPN-службе.
- [ ] Отдельно проверены остановка VPN-службы и системный режим блокировки соединений вне VPN; фактическое поведение и несовместимости с прямыми маршрутами записаны.

## 5. Решение о переходе к своему приложению

- [ ] Основные сценарии подключения и маршрутизации работают в обеих сетях.
- [ ] Ошибки и непроверенные условия перечислены явно; у каждого существенного ограничения есть решение либо согласованное изменение требований.
- [ ] Проверены лицензии и возможность встраивания выбранного движка в своё приложение.
- [ ] Выбран стек первой версии и определён минимальный объём Android-приложения.

Успех прототипа подтверждает пригодность выбранной схемы в проверенных условиях, но не гарантирует работу при будущих блокировках. Поведение готового клиента также не заменяет проверку собственного приложения после реализации.
