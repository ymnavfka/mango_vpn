# Требования к первой версии

Статус: исходные требования по итогам обсуждения. Выбор движка, протокола и хостинга требует проверки прототипом.

## Цель и условия использования

Создать личный VPN для обхода блокировок при использовании интернета в России. Приложение должно оставаться включённым и автоматически выбирать прямое подключение или зарубежный сервер для каждого соединения.

Первая платформа — Android. Тестовые сети: мобильный интернет Мегафона и домашний интернет ВестКолл Домашние сети. Существующий AdGuard VPN сохраняется как запасной вариант на время экспериментов, но при проверке нашего подключения должен быть выключен.

Собственное приложение — обязательная цель проекта: готовый клиент используется только для предварительной проверки сервера, протокола и правил. Готовый сетевой движок отвечает за протокол и криптографию; собственную криптографию не разрабатываем.

## Автоматическая маршрутизация

Правила применяются в следующем порядке; первое совпадение определяет маршрут:

| Приоритет | Условие | Маршрут |
| --- | --- | --- |
| 1 | Пользовательское исключение для домена | Указанный пользователем: напрямую или через VPN |
| 2 | Локальная сеть и локальные адреса | Напрямую |
| 3 | Домен в зоне `.ru` или `.рф`, включая поддомены | Напрямую |
| 4 | Домен в обновляемом наборе российских сервисов | Напрямую |
| 5 | Остальной трафик, включая нераспознанные назначения | Через VPN |

Сопоставление доменов должно учитывать границы доменных меток, регистр и представление международных доменов (IDNA). Например, `example.ru.external.com` не относится к зоне `.ru`.

Приложение не выключает VPN целиком при открытии российского сайта: прямые соединения и соединения через сервер работают одновременно. Правила выбирают маршрут для новых соединений; изменение правила может потребовать переподключения существующего соединения.

Набор российских сервисов должен включать известные домены вне `.ru` и `.рф`. Источник, лицензия, состав и механизм обновления набора ещё не выбраны. Обновление не должно удалять ручные исключения; при неудачном обновлении сохраняется последний рабочий набор.

Не используем географию IP как безусловный признак принадлежности сайта России. Не делаем автоматическую прямую попытку подключения для трафика, назначенного на VPN.

## Минимальные функции Android-приложения

- Импорт конфигурации одного сервера без обязательной регистрации и отдельного управляющего backend.
- Подключение и отключение одной кнопкой.
- Понятные состояния: отключено, подключается, подключено, переподключается, ошибка.
- Восстановление соединения после смены сети и временной потери доступа.
- Автоматическая маршрутизация по правилам выше.
- Добавление, изменение и удаление ручных исключений для доменов, с явным выбором применения к поддоменам.
- Просмотр выбранного маршрута и причины решения для диагностируемого соединения. Если домен определить нельзя, интерфейс должен честно это показывать.
- Локальная диагностика без ключей, токенов и содержимого трафика. Историю посещений не сохраняем по умолчанию.

## DNS, безопасность и сбои

- DNS и обработка IPv6 входят в первую версию, а не откладываются на будущие платформы.
- Для назначений через VPN DNS не должен незаметно уходить к провайдеру напрямую. Для прямых назначений политика DNS должна обеспечивать работоспособность локальных и российских сервисов.
- При недоступности VPN-сервера трафик, назначенный на VPN, блокируется до восстановления соединения. Прямые маршруты должны продолжать работать, пока VPN-служба приложения активна.
- Аварийное завершение приложения, остановку службы и системную блокировку соединений вне VPN проверяем отдельно: нельзя обещать сохранение маршрутизации после остановки службы. Совместимость системного режима блокировки с прямыми маршрутами требует проверки.
- Секреты конфигурации не попадают в репозиторий, журналы или диагностический экспорт. Используется защищённое хранение с учётом возможностей Android.
- Для каждого устройства предусматривается отдельный доступ с возможностью отзыва.
- Расшифровка HTTPS и установка собственного корневого сертификата не требуются.

## Ограничения автоматического определения

Правило по доменной зоне однозначно при известном домене, но принадлежность сервиса стране не всегда однозначна. Одна страница может обращаться к нескольким доменам, каждый из которых получает собственный маршрут. Списки сервисов могут быть неполными или устаревшими.

Приложения с собственным зашифрованным DNS, скрытыми именами назначения или обращениями по IP требуют отдельной проверки. Для нераспознанного трафика действует маршрут по умолчанию — VPN. Стопроцентное распознавание всех российских сервисов и безусловная устойчивость к блокировкам не обещаются.

## Сервер и бюджет

- Один VPS за пределами России, первоначально с помесячной оплатой.
- Общая регулярная стоимость сервера — не более 300 ₽ в месяц, включая обязательные доплаты и комиссии. Ориентир для поиска — 200–250 ₽ в месяц.
- Годовые расходы на сервер должны быть ниже текущей подписки: 3949 ₽. Валютные изменения, комиссии и цену продления учитываем перед оплатой.
- Предпочтительна оплата российской картой. Другие способы рассматриваются, если подходящих предложений нет.
- Исходный ориентир ресурсов: Linux, 1 vCPU, около 1 ГБ RAM и публичный IPv4. Достаточность ресурсов проверяется экспериментом.
- До покупки проверяются лимит трафика, скорость, правила использования VPN, итоговая цена и доступность из тестовых сетей, насколько это возможно до оплаты.

Конкретный провайдер и тариф не выбраны. Два протокола на одном IP не защищают от блокировки самого IP.

## Технические кандидаты

- Android: Kotlin и нативный интерфейс, интеграция с системным `VpnService`.
- Движок клиента: sing-box как первый кандидат для маршрутизации и DNS.
- Соединение с сервером: VLESS + REALITY как первый кандидат.
- AmneziaWG рассматривается как альтернативный вариант при необходимости.

Это не окончательный выбор стека. До реализации нужно проверить совместимость конкретных версий, способ встраивания, лицензии и пригодность для последующих платформ.

## Последующие платформы и границы первой версии

В дальнейшем: iOS, macOS, Linux и Android TV. Общие правила и формат конфигурации желательно переиспользовать, но системная интеграция и интерфейс потребуют адаптации. Для Android TV отдельно проверяется управление пультом.

Собственное iOS-приложение требует отдельной оценки подписи, Network Extension и расходов на распространение. Эти расходы не включены в бюджет сервера; при необходимости сначала используется совместимый готовый клиент.

В первую версию не входят оплата подписок, публичная регистрация, административная панель, несколько стран, автоматическая ротация серверов и одновременная разработка всех платформ.

## Следующий этап

Сначала проверяем сервер, соединение и маршрутизацию готовым Android-клиентом по [чек-листу прототипа](prototype-checklist.md). После успешной проверки переходим к собственному приложению. Покупка сервера и реализация кода — отдельные следующие действия.
